# web-search-gym

Training gym for web-search agents. Qwen3 + Exa searcher, trained via SFT then GRPO,
evaluated on BrowseComp.

## Tech stack

- Python ≥3.10, `uv` for env management
- Anthropic SDK (searcher calls via native or OpenRouter)
- `exa-py` for web search
- `trl` + `peft` + `transformers` for SFT (and later RL)
- `click` + `rich` for CLI / output
- `pytest` for tests

## Non-negotiable architectural rules

1. **Each agent owns its tools / prompts / harness inside
   `agents/<name>/`.** `core/` holds only the genuinely shared scaffolding:
   `tools.py` (filter fragments + COMMIT_MEMORY_SPEC), `prompts.py`
   (THINKING_INSTRUCTION, BROWSE_EXTRACT_PROMPT, EXTRACTOR_PROMPT),
   `llm.py` (client + retry helpers), `scratchpad.py` (fuzzy_replace),
   `context.py`, `exa_client.py`, `extractor.py`, `browse.py`, `trace.py`,
   `types.py`. Per-agent assets live in
   `agents/<name>/{tools,prompts,harness}.py`.
2. **`BaseAgent` has class-level slots.** Every subclass populates
   `TOOL_SCHEMAS` and `SYSTEM_PROMPT` (or sets them to `None` for
   non-tool-calling agents like `exa_deep`). The parity test iterates
   `discover_agents()` and asserts conformance — new agents land in
   the test automatically.
3. **Never fork a shared fragment.** `EXA_SEARCH_FILTERS` and
   `COMMIT_MEMORY_SPEC` in `core/tools.py` are spread / referenced by
   every agent that uses them. Re-authoring filters from scratch fails
   `tests/test_core_parity.py::test_agent_search_includes_canonical_exa_filters`.
4. **Agents ≠ models.** A directory under `agents/` is a harness shape.
   Adding a new model means one YAML in `models/`, not a new agent directory.
5. **Scratchpad tool returns status only.** Never inline full scratchpad
   content into tool results (the `<scratchpad>` system block shows it).
6. **Exa client uses `search(contents={"summary": {...}})` only** —
   never swap the content shape (no `highlights`, no `text`, no
   `get_contents`) for the lean_searcher path. The summary query may
   differ from the search query via `summary_query`; both single-query
   and split-query forms are in-contract because the tool schema exposes
   `summary_query` and training data captures whichever the model used.
7. **Source bank is a first-class Trace field.** Never re-fetch
   content; downstream stages read from the Trace.

## Datasets

Two benchmarks, selected via `--dataset`:

- **browsecomp** (default) — 1266 XOR-encrypted tasks, LLM-judge grading. Splits
  in `bench/splits.yaml`: `dev` (10), `smoke` (50), `full` (all).
- **filterbench** — our synthetic multi-hop + filter benchmark in
  `bench/filterbench/<split>.jsonl`. `test` has 33 questions across 11 cells
  (hop_count × filter_count ∈ {1..4} × {0..2}, with filter_count ≤ hop_count).
  Generated by `synth/gold_path_generation.py` (v3 iterative chain-builder,
  per-hop Haiku cold-check, forced-submit fallback). Judge and extractor are
  shared with BrowseComp — golden_answer → correct_answer, no format change.

```bash
make bench AGENT=lean_searcher MODEL=claude_sonnet DATASET=filterbench SPLIT=test
uv run python -m synth.gold_path_generation --mode test --seed 456
```

## Current state

Scaffold + filterbench v3 generator (33-question test set) + DeepSearchQA
(Google's 900-task multi-step research bench) wired as a dataset option
with its official gemini-2.5-flash autorater. lean_searcher, three
exa_deep tiers, chroma_agent, and `agent_dd` (single-rollout DR-Tulu-style
harness with search/browse_page/commit_memory/answer) available as
baselines. Best on DSQA domain2 (32 tasks): agent_dd 8-cycle + commit_memory
at 43.8% fully-correct / 50.4% F1 — see docs/agent-dd-dsqa.md. No agents
trained yet.
